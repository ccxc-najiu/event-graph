# 设计说明

## 1. 事件定义图与实际经历

世界包含预定义事件集合 E、结果定义集合 R，以及连接集合 C：

```text
owner: R → E
connection: (source_result, target_event, kind, target_role)
kind ∈ {trigger, related}
```

每个结果只归属于一个事件。多个事件若需要输出语义相近的事实，当前版本应使用不同结果 ID，并在消费端明确连接；没有隐式的结果别名或类型继承。

`Event` 是事件类/模板，`Execution` 是某次实际发生。模板可以反复执行，执行记录用唯一 ID 区分。事件之间的类型依赖允许循环；循环是否有足够的起始事实、不发生永久不可达，不由当前库自动证明。

经历不会预分配所有可能结果。每次执行先计算完整联合输出，通过合法性检查后才一次性追加。失败或未选择发生的事件都不产生记录。

## 2. 七项属性与派生视图

`Event` 自身保存时间、地点、参与角色和内部流程。图通过 `schema(event_id)` 补齐：

```text
trigger_conditions = 所有 trigger 入边的来源结果
related_items      = 所有 related 入边的来源结果
outputs            = owner 为当前事件的所有结果
```

同一 `(source_result, target_event)` 最多存在一条边，保证两个输入集合不相交。当前版本不支持同一结果类型分别绑定到同一目标事件的多个角色；这需要未来引入独立的输入端口 ID。

触发条件的集合语义是 AND：全部存在才允许触发。相关项是可选事实，缺少一项只是让输入集合中没有它。

## 3. 多主体绑定

事件定义的角色槽位在执行时必须全部且恰好绑定。一个人物可以绑定多个槽位；如果某类事件要求角色必须由不同人物承担，应在未来增加角色约束或在调用端检查。

一个输出结果可以指定多个收件角色。执行时角色映射为人物 ID，结果记录保存人物集合。世界级结果没有个人收件者。

连接指定 `target_role` 时，只匹配绑定人物拥有的结果。未指定时，匹配当前任一参与者的结果，或世界级结果。其他未参与人物的个人结果不可见。此可见性用于结果归属匹配，不等同于主观知识、传闻或保密机制。

## 4. 输入域与内部流程

对于事件 A，运行时提取：

```text
X = 实际匹配的历史结果 ∩ related_items(A)
Y = flow_A.resolve(X)
```

`Y` 必须是 `outputs(A)` 的子集。它是一个整体的多角色结果，不会对每个人独立抽样后再拼接。

`TableFlow` 复制并冻结调用者提供的表，键、值都是 `frozenset`。全覆盖检查利用“所有键均为合法子集，且键数量等于 2^N”判断，不实际枚举所有子集。默认分支更适合较大的相关项集合；自定义 `Flow` 可以实现决策树、共享分支或者随机规则。

`input_domain` 表示调用者声明的可达域。它不是静态求解器：新事件即使没有改变某个目标的输入边，也可能使过去不可达的输入组合出现。当前实现会在运行时拒绝域外输入，而不会自动补出流程。对希望任意扩展的流程，优先使用明确的默认分支或自行维护域假设。

## 5. append 事务

一次 append 按以下顺序执行：

1. 复制事件、结果和连接容器。
2. 加入新定义与连接，应用调用者提供的流程更新。
3. 校验结果所属事件、角色、边端点、重复连接与输入集合不相交。
4. 比较已有事件的输入连接和输出集合，要求所有发生变化的已有事件显式提供流程更新。
5. 对候选图中所有流程运行 `validate`。
6. 构建正反向索引，增加图修订号，一次性提交。

新事件可引用同一批新增或已存在的结果，因而不要求输入参数按依赖拓扑排序。已有事件的流程也可以通过只有 `flow_updates` 的 append 更新。

没有提供更新、输出越界、输入覆盖不足等错误都发生在提交前。图拥有的数据保持原状，调用者可以修正参数后重试。

新增/改变的事件才替换对象，其他事件保留对象引用；校验会遍历整个候选图，以便发现仍引用退休结果的表项。当前实现偏向简单明确，没有维护增量求解器。入边、结果消费者索引随成功更新一起重建。

## 6. 替换结果

`replace_result` 是同一事务机制上的组合操作：

```text
删除旧端口和所有旧出边
+ 添加属于同一事件的新端口
+ 添加调用者指定的新连接
+ 应用来源事件和受影响消费者的流程更新
```

旧结果 ID 进入退休集合，后续不能重新使用，避免旧历史被误解释成新含义。来源事件的输出改变，必须更新其流程。旧目标的触发边被移除可能放宽条件，也必须由显式流程更新确认。

历史结果保存完整的 `Result` 定义快照，不依赖当前图查找。因此替换后旧记录仍能展示，但不会自动匹配新结果 ID。图修订号记录执行时使用的定义版本编号；当前实现不保存全部旧流程版本，因此仅有修订号不足以重放旧流程或随机选择。

## 7. 执行与原子性边界

事件不会因为满足条件而自动执行。调用者首先选择事件，再调用 `execute`。执行检查角色、时间、地点和触发条件，提取相关项，计算结果，检查所有输出合法，最后追加一条完整记录。

历史执行时间不得倒退，允许相同时间有多个执行。查询旧时刻的可触发性时，未来结果不参与匹配。所有结果立即在本次执行时间产生，没有进行中事件或中途输入模型。

事务保证覆盖库拥有的定义容器和历史容器。自定义 Flow 的 Python 代码可以访问外部世界，其任意副作用无法回滚。`validate` 必须纯净，`resolve` 应仅计算输出；不应在回调中重入修改同一个图。库不提供跨线程并发写入保证。

## 8. 扩展方向

后续可以在已有结构上增加独立输入端口、复合触发表达式、资源状态投影、持久化适配器、时间调度和可视化编辑器。概率流程通过继承 Flow 实现；为可重现模拟，应显式管理随机数源并记录必要信息。

这些能力不在当前版本中隐式推断，以保持事件定义、连接和流程修改之间的关系清楚。
